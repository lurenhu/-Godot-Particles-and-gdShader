# 第十三课：本机实测分析

制作日期：2026-10-13。[原始数据](benchmark-example.json) · [完整运行日志](benchmark.log) · [返回讲义](README.md)

## 条件

- Godot 4.7.1 stable official，NVIDIA GeForce RTX 5060 Ti。
- Forward+ / Vulkan；VSync 关闭，Engine.max_fps=240。
- 请求启动窗口 1200×800，**报告实际视口为 1152×768**；使用实际值，不拿请求值冒充渲染尺寸。
- 每项 3 秒预热、2 秒采样，三轮，中间一轮逆序；固定相机与种子 137。
- 独立调试运行，非导出包基准；未记录 GPU 时钟与温度，未做硬件锁频。
- `smoke_only=false`、`aborted=false`，共 30 行，每项每轮 GPU 有效样本 481 个。

相同的中位数不表示所有原始值相同：基线第一轮原始 GPU 数组包含 8 个不同值，数量减半包含 6 个，卡片加大包含 12 个。计时读数精度和分布使三轮中位数相同，不能据此声称系统不存在噪声。

所有项目的应用帧间隔中位数都约 4.167 ms；第一轮全屏扭曲的帧间隔 P95 约 4.21 ms，其余大多约 4.17 ms。更精确的值和视口 CPU 摘要请看报告。

## 能得到什么判断

1. **当前帧间隔首先受 240 限帧约束。** 本次没有证明 GPU 已成为整体帧率瓶颈。
2. 在所测绘制参数中，卡片加大的 GPU 增量最大：相对基线约增加 0.185 ms；采样增加约 0.060 ms。说明这组条件下，减少不必要的覆盖面积值得优先尝试，但不是所有项目的通用排序。
3. 中档相对高档的视口 GPU 中位数约减少 0.056 ms，低档约减少 0.072 ms。局部指标降幅约 46% 和 59%，**不代表整个程序快了同样比例**；帧间隔没有同步下降。
4. 30 Hz 的视口 GPU 中位数不变，不能推出模拟频率没有成本。这里不是独立粒子模拟计时器，整体又受限帧约束。
5. 湍流和碰撞既改计算又改分布。它们的小幅时间差不足以单独证明计算阶段的成本，下一步应结合 Visual Profiler。

## 视觉取舍

实际查看了高、中、低档截图：三档保留了发射区域和下落方向，低档明显更稀疏、更透，不能称为无损替换。若作品要求浓密烟墙，需重调视觉设计，再重新测量；本课仅把这些档位作为可比较的候选方案。

要把本课变成自己的优化结论，请在目标设备上重跑三轮，并用效果实际使用的屏幕尺寸和密度测试。不要直接复制这张表的数值作为项目预算。
